COLOSSUSX NETWORK GUIDE

Validators &
Common Miners

Two roles, one network. Validators finalize blocks. Common miners receive user transactions through public RPC and prove that they accepted them.

Chain ID 10101919 Currency colossusX · CLX Decimals 18
CONSENSUS & FINALITY

Validators

Create and verify blocks, run HotStuff finality, and decide the final state of the chain.

Their core job is block production, verification, and finalization. They do not need to expose public RPC endpoints.

PUBLIC TRANSACTION ADMISSION

Common miners

Open public RPC endpoints, receive user transactions, create signed CommonTxAdmission records, and relay admissions to the validator leader.

This admission layer operates in front of the validator network. Common miners do not replace validator consensus.

FROM SUBMISSION TO FINALITY

How a transaction reaches the chain

  1. 01

    Choose an RPC

    Users can send transactions through any common miner RPC endpoint and switch to another if one is unavailable.

  2. 02

    Sign the admission

    A common miner accepts the transaction and relays a signed admission to the validator leader.

  3. 03

    Verify & finalize

    Validators verify the proofs and execute transactions, then finalize the chain state through consensus.

TxQUIC access and authentication

TxQUIC verifies each sender's signature. Optional AllowedSigners and AllowIPs settings restrict a local endpoint only when populated. Empty lists accept any correctly signed sender from any source IP. The supplied network configuration leaves both filters empty; this guide does not independently verify live endpoint settings. Validator committee authentication remains required.

COMMON RPC REWARD RULE

A signs. B receives the reward.

Every admission identifies a signing account A and a distinct reward recipient B. A signs the complete proof, including B. Validators require matching A and B in the reward record; their local reward preference does not determine block payouts.

ACTUAL TRANSACTION FEE

The fee calculation stays the same

actualTxFee = gasUsed * effectiveGasPrice
commonRpcReward = floor(actualTxFee / 5)
commonRpcBurn = actualTxFee - commonRpcReward
20% to B, rounded downRemainder burned
DIRECT CREDIT TO B

No claim transaction needed

After all transactions in the block have executed, rewards are aggregated by recipient and credited directly to B.

  • No intermediate credit to A or automatic transfer.
  • No contract call to B or claim transaction.
  • A missing B prevents a new admission. Payment never falls back to A.

Other reward types retain their existing recipients and amounts. Fee calculation and rounding are unchanged.

Common miners can earn more transaction admission rewards as more users send transactions through their public RPC endpoints. Receiving these fees does not make B or the common miner operator a validator.

RPC REFERENCE

Read the admission and reward records

Use eth_getTransactionReceipt and eth_getTransactionByHash, or the console equivalents eth.getTransactionReceipt(txHash) and eth.getTransaction(txHash).

Common RPC admission and reward fields
Field Meaning
commonTxApprover Admission signer A.
commonTxRewardRecipient Actual reward recipient B.
commonTxApproverReward Common RPC fee reward credited to B. The existing field name is retained.
commonTxBurn Burned remainder of the actual fee.
commonTxAdmissionRoot Block commitment to the signed admissions and references.
commonTxRewardRoot Block commitment to reward records.
commonTxAdmissionChainId Chain ID bound to the proof.
commonTxAdmissionKeyBlockNumber Admission's key-block boundary.
commonTxAdmissionTimestamp Signed admission timestamp.
commonTxAdmissionSignature A's signature over the admission payload.

Check a receipt in the console

For a client connected to public RPC, inspect the receipt and B's balance.

Compare B's balance against its initial balance and ordinary transfers. A balance increase alone does not establish the source of a reward. 

var receipt = eth.getTransactionReceipt(txHash);
receipt.commonTxApprover;
receipt.commonTxRewardRecipient;
receipt.commonTxApproverReward;
receipt.commonTxBurn;
eth.getBalance(receipt.commonTxRewardRecipient);

Validators remain responsible for verifying proofs, reward amounts, roots, signatures, chain identity, and final state.
